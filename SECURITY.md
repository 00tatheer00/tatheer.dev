# Security Policy

## Reporting a vulnerability

Please do not publish exploitable vulnerability details in a public issue.

Use GitHub's private vulnerability reporting feature for this repository when it is enabled. If private reporting is unavailable, contact the repository maintainer through the contact details on the GitHub profile and include:

- A concise description of the issue
- Affected files, routes, or versions
- Reproduction steps and potential impact
- Any suggested mitigation

## Responsible disclosure

Allow reasonable time for investigation and remediation before public disclosure. Do not access, modify, or retain data that does not belong to you.

## Security expectations

- Never commit secrets, API keys, tokens, passwords, or production data.
- Keep privileged credentials server-side.
- Validate inputs and enforce authorization at trusted server boundaries.
- Keep dependencies and deployment configuration reviewed.
