# Contributing

Thank you for considering a contribution.

## Before you start

1. Read the project README and architecture notes.
2. Check existing issues and pull requests to avoid duplicate work.
3. For larger changes, open an issue first to discuss scope and approach.

## Development workflow

1. Fork the repository or create a feature branch.
2. Install dependencies using the documented package manager and lockfile.
3. Configure local environment variables from the example file.
4. Make a focused change with clear naming and maintainable structure.
5. Run relevant tests, type checks, linting, and production builds.
6. Update documentation when behavior, configuration, or setup changes.
7. Open a pull request using the repository template.

## Pull request expectations

- Explain the problem and the solution.
- Keep changes scoped and reviewable.
- Include screenshots for user-facing changes.
- Document migrations and environment changes.
- Never include credentials, customer data, generated dependencies, or local environment files.

## Code quality

Prefer readable code, explicit validation, secure authorization, and consistent error handling. Do not claim a test or check passed unless it was actually run.
